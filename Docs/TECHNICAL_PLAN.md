# الخطة التقنية

## العميل
Unity 3D / C# مع إعداد Android، وتحكم لمس، ومشهد اختبار أولي. يجب استخدام LOD وتقليل كثافة المجسمات واختبار الأداء على أجهزة متوسطة ومنخفضة الإمكانات.

## الحسابات
- Guest: إنشاء هوية مجهولة عبر Firebase Authentication.
- Google: تسجيل OAuth عبر Firebase Authentication.
- ربط حساب الضيف بحساب Google عبر link credential حتى لا يضيع التقدم.
- ملف اللاعب: PlayerId وDisplayName وLevel وWins وLosses وRating.
- قواعد Firestore تمنع العميل من تعديل التقييم ونتائج المباريات مباشرة.

## المطابقة
- طابور 1v1.
- مطابقة أولية حسب التقييم والمنطقة وجودة الاتصال.
- إلغاء البحث عند مغادرة الطابور.
- إنشاء MatchId وغرفة خاصة بعد العثور على لاعبين.
- معالجة انقطاع الاتصال والعودة للمباراة وفق مهلة محددة.

## اللعب الجماعي والتحقق
يجب اختيار خدمة Multiplayer مناسبة قبل التنفيذ النهائي (مثل Photon Fusion أو خادم مخصص). الخادم هو المرجع النهائي لمواضع اللاعبين المقبولة وإطلاق النار والإصابات والنتيجة. لا يعتمد النظام على ادعاء العميل بأنه أصاب الخصم.

## خريطة الصحراء
المساحة التصميمية 4 × 4 كم (16 كم²). يوصى بتقسيم العالم إلى قطاعات واستخدام Terrain وLOD وOcclusion Culling والتحميل التدريجي عند الحاجة. يجب اختبار الرؤية البعيدة والضباب والأداء على الجهاز المستهدف.

## نموذج الطلقة
النموذج الأولي يستخدم الجاذبية وتسارع الرياح لتصور المسار. قيم الرياح والضرر وسرعة المقذوف النهائية تضبط كلعبة ترفيهية. حسابات العميل ليست حاسمة في المنافسة.

## مراحل التسليم
1. مشهد محلي للصحراء وحركة اللاعب.
2. سلاح ومنظار وتحكم لمس.
3. حساب ضيف وGoogle وربط الحسابين.
4. مطابقة 1v1 وغرفة لعب.
5. اختبار جهازين وشبكات مختلفة.
6. تحسين الأداء وبناء APK موقّع.
